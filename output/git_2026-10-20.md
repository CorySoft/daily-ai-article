# 你的电脑可能正在被“偷窥”，而这个零依赖工具能让证据开口说话

在数字安全领域，我们习惯于用杀毒软件来查杀恶意代码，却常常忽略一个更隐蔽的威胁：**间谍软件（Spyware）**。尤其是像 AdFection 这样的高级持续性威胁，它不需要你点击任何链接，仅凭渲染广告的瞬间就能植入痕迹。面对这种“零点击”攻击，传统的在线扫描器往往因为需要上传日志或联网验证而变得既慢又不安全。

今天推荐的开源项目 **Zero Breach** 提供了一个截然不同的思路：**完全离线、纯本地、只读扫描**。它不依赖任何第三方库，甚至不需要网络权限，专门用于检测 AdFection/Candiru 间谍软件留下的数字残骸。这不仅仅是一个扫描器，更是一份严谨的**数字自我证词**。

## 为什么我们需要一个“不求人”的本地扫描器？

Zero Breach 的核心痛点在于解决高级安全事件中的**隐私悖论**。当你怀疑自己成为国家级或企业级监控目标时，你很难放心地将浏览器日志、DNS 缓存或文件指纹上传给某个在线扫描服务。毕竟，这些元数据本身就可能是攻击者感兴趣的目标。

Zero Breach 的设计哲学非常克制：
- **无网络依赖**：整个扫描过程在本地内存和磁盘之间完成，绝不发起任何 HTTP 请求。
- **只读权限**：工具只读取浏览器历史、Cookie 路径、系统启动项等只读区域，绝不修改系统状态。
- **零依赖**：默认模式仅使用 Python 标准库，无需安装复杂的分析框架，下载即可运行。

这种“低权限、离线化”的特性，使得它特别适合记者、活动家或安全研究人员在疑似遭受定向攻击后的**初步自查**阶段使用。它不试图清除病毒（那是 EDR 的工作），而是试图回答一个问题：“我的设备上是否还残留着特定威胁活动的物理证据？”

## 核心特性：从“黑名单匹配”到“证据分级”

大多数安全工具输出的结果是二元的：感染或安全。但 Zero Breach 引入了一个极具价值的概念：**证据强度分级**。

### 1. 多维度痕迹追踪
它不只看文件哈希，而是构建了一个多维度的检测矩阵：
- **浏览器层**：深入 Chrome、Edge、Firefox 等主流浏览器，检查历史、Cookies（仅主机名和时间戳）、Local Storage、Service Worker 缓存。
- **系统层**：扫描自动启动注册表项、已知恶意软件路径、DNS 解析器缓存。
- **文件层**：对用户可写目录进行 SHA-256 指纹比对，识别已知样本。

### 2. “未检查项”的诚实披露
这一点令人印象深刻。工具不仅告诉你“发现了什么”，还明确列出**“它没能检查什么”**。
> “A clean result is not a clean bill of health.”（干净的扫描结果不等于健康证明。）

README 中反复强调，此类高级间谍软件（如 Candiru）会主动清除痕迹，且 Windows 默认不记录 DNS 历史。Zero Breach 通过量化“检测覆盖率”来管理用户预期，避免用户产生虚假的安全感。这种**认知诚实**（Cognitive Honesty）在开源安全工具中并不多见。

### 3. 模块化与扩展性
虽然默认无依赖，但项目支持可选的 **YARA-X** 引擎扩展。如果你需要更高级的模式匹配（如检测特定的内存注入行为或复杂的文件结构特征），可以加载 YARA 规则集。这种“默认极简，按需增强”的设计，平衡了易用性与专业性。

## 快速上手：五分钟完成一次数字体检

作为资深开发者或极客，你可能担心部署复杂度。但 Zero Breach 的极简主义让你惊喜。

1. **获取代码**：
   ```bash
   git clone https://github.com/interplains/zero-breach.git
   ```
2. **环境准备**：
   只需 Python 3.8+ 环境。无需 `pip install` 任何包（默认模式）。
   ```bash
   python -m venv venv && source venv/bin/activate # Windows 用户请调整命令
   ```
3. **执行扫描**：
   ```bash
   python main.py --full-scan
   ```
4. **解读报告**：
   工具会在本地生成一份 JSON 和可读的 Markdown 报告。重点关注：
   - `evidence_confidence`：高/中/低。
   - `coverage_gaps`：哪些目录因权限不足或未开启日志而无法扫描。

**注意**：扫描前建议关闭浏览器进程，以避免文件锁定问题。由于是只读操作，你可以放心地在生产环境或工作机上运行。

## 技术亮点分析：为何标准库足以应对？

在安全领域，我们常迷信重型框架（如 YARA、Snort、Suricata）。但 Zero Breach 证明了**在特定场景下，Python 标准库 + 严谨逻辑 > 复杂依赖**。

- **性能瓶颈的转移**：扫描本身 I/O 密集而非 CPU 密集。Python 的 `hashlib` 和 `os` 模块足以高效遍历文件系统。将复杂性交给脚本逻辑（如解析 SQLite 浏览器数据库、正则匹配 URL 模式），而非外部二进制。
- **可审计性**：由于没有编译后的二进制插件或闭源组件，审计人员可以逐行阅读代码，确认它确实没有后门或数据外传逻辑。这对于涉及敏感数据的安全工具至关重要。
- **CI/CD 成熟度**：项目在 CI 中覆盖了 Python 3.8–3.12，并在 Windows、macOS、Linux 上进行测试。v0.1.6 版本还修复了 COM 文件路径解析中因文件夹名包含可执行扩展名导致的误报，体现了对边界条件的细致打磨。

**对比传统 EDR**：
- **EDR**：实时监控、主动拦截、云端联动。适合日常防护，但数据流经网络。
- **Zero Breach**：事后取证、离线分析、本地闭环。适合怀疑被定向攻击时的**逆向排查**，而非日常防御。

它们不是替代关系，而是互补关系。Zero Breach 填补了“高级威胁事后取证”这一空白。

## 适用场景与未来展望

### 谁该用它？
1. **高风险用户自查**：记者、异见人士、活动家。若怀疑设备被植入 Candiru，用它作为第一道本地筛查。
2. **数字取证分析师**：在合法授权下，用于快速提取特定间谍软件活动痕迹，作为后续深度 forensics 的线索。
3. **安全意识培训**：向团队演示“零点击攻击”的残留痕迹，比单纯讲 PPT 更具冲击力。

### 局限性与建议
- **时效性**：间谍软件痕迹通常会在数周内被清理。此工具适用于**近期**（1-3个月）的排查。
- **非万能**：README 明确指出，它不能替代系统更新和广告过滤。
- **建议行动**：
  - 结合 **AdBlock** 等扩展减少广告曝光。
  - 启用操作系统的 **DNS 历史记录**功能（如 Windows 的 WMI 或 macOS 的日志配置），以便下次扫描获得更高覆盖率。
  - 若发现高置信度证据，立即联系专家（如 Access Now 或 Amnesty International Security Lab），而非自行尝试清除。
